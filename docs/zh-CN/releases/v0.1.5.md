# M365 MCP Server v0.1.5

## 通用 m365-mail Skill

- 将原来的四份 WorkBuddy 邮件 Skills 合并为一个可独立安装的 `m365-mail`，供
  Python 服务器版、Windows .NET 和 Windows Go 共用。
- 根据当前 MCP 连接暴露的工具说明和输入 Schema 选择受支持的操作流程，兼容客户端
  添加的工具名前缀；只有当前连接暴露可选工具时才调用。
- 包含完整中英文指令、安装/迁移指南，以及按需读取的远端上传参考文件。安装包只有
  一个 `SKILL.md` 入口。
- 保留明确发送批准或受限自动化授权、最终草稿/附件核对、不可信内容处理，以及结果
  不明时避免重复写入的规则。Skill 元数据不会预授权邮箱或 Shell 操作。
- 明确附件列表的 `size` 是服务方元数据，获取后的 `content_length` 才是实际解码
  字节数，不能将二者当作可互换的完整性校验值。

## 各版本能力

| 能力 | Python 服务器版 | Windows .NET | Windows Go |
| --- | --- | --- | --- |
| 邮件工具 | 11 项；开启服务器管理的 OAuth 后为 13 项 | 11 项 | 12 项 |
| 草稿附件参数 | 二进制上传后传 `draft_id`、`upload_handle` | `draft_id`、可选 `relative_path`；省略时打开选择框 | `draft_id`、必填 `relative_path`；无选择框 |
| 附件文本 | PDF、DOCX、XLSX、PPTX、TXT、Markdown | UTF-8 文本、CSV、JSON、XML | PDF、DOCX、XLSX、PPTX、TXT、Markdown |
| 附件下载 | 仅服务器管理的 OAuth 模式；HTTPS URL | 不提供 | 在 EXE 所在电脑打开的 HTTP URL |
| 远端上传辅助能力 | 服务器提供上传句柄及可选 OAuth Push Grant | `inspect-attachment`、`push-attachment` | 不提供辅助命令 |

本机路径附件使用操作者配置的 `M365_ATTACHMENT_ROOT`，Go 要求正斜杠，例如
`reports/weekly.docx`。远端上传使用可信二进制上传器及 `upload_handle`；客户端本地
路径不等于已上传文件。下载链接是短时、一次性的访问凭据。

## 安装或迁移 Skill

1. 下载 `m365-mail-skill.zip` 和 `SHA256SUMS.txt`，将 ZIP 的 SHA-256 与对应校验记录
   核对后再解压。
2. 将解压后的完整 `m365-mail` 文件夹（含 `references/`）复制到一个客户端 Skill 目录：

| 客户端 | 个人目录 | 项目目录 | 显式调用 |
| --- | --- | --- | --- |
| Codex CLI / IDE | `~/.agents/skills/m365-mail/` | `<项目>/.agents/skills/m365-mail/` | `$m365-mail` |
| Claude Code | `~/.claude/skills/m365-mail/` | `<项目>/.claude/skills/m365-mail/` | `/m365-mail` |

Windows PowerShell，安装到个人 Codex 的示例：

```powershell
Get-FileHash .\m365-mail-skill.zip -Algorithm SHA256
Expand-Archive -LiteralPath '.\m365-mail-skill.zip' -DestinationPath '.\m365-mail-skill'
$m365SkillParent = Join-Path $env:USERPROFILE '.agents\skills'
New-Item -ItemType Directory -Path $m365SkillParent -Force | Out-Null
Copy-Item -LiteralPath '.\m365-mail-skill\m365-mail' -Destination $m365SkillParent -Recurse
```

Claude Code 将 `.agents\skills` 改为 `.claude\skills`。其他 Agent Skills 客户端
使用其文档指定的目录；未发现 Skill 时刷新或重启客户端。`SKILL.md` 中的中文链接
指向完整中文版，保留一个入口，按用户对话语言回复。

3. 从客户端移除旧的 `outlook-mail`、`outlook-mail-compose`、
   `outlook-mail-management`、`outlook-attachments` 副本，或替换旧 WorkBuddy 包，
   避免重复指引。
4. MCP 连接仍需单独配置及登录，Skill 不配置认证，也不授予权限。WorkBuddy 远端 OAuth
   连接器模板仍在源码包的 `workbuddy/` 目录，打包其内容，使 `connector-meta.json`、
   `mcp.json`、`icon.svg`、`skills/` 位于 ZIP 根目录。Skill ZIP 本身不是连接器包。

已有的有效加密登录状态及 `stdio` 配置可继续使用。Go v0.1.3 及以前版本升级后，
将 `args: ["serve"]` 改为 `args: ["stdio"]`，或重新执行 `connection`；
`serve --http --port 8000` 改为 `http --port 8000`。重新登录会轮换 Go 的本机 HTTP
Token，之后需重新生成 HTTP 配置。

## 发布文件与验证

| 文件 | 内容 |
| --- | --- |
| `m365-mail-skill.zip` | 通用 Skill、完整中英文指令、安装指南、远端上传参考 |
| `m365-mcp-windows-local-amd64.exe` | .NET NativeAOT，AMD64 |
| `m365-mcp-windows-local-go-amd64.exe` | Go，AMD64 |
| `m365-mcp-windows-local-go-arm64.exe` | Go，ARM64 |

每个独立 EXE 附有 `.exe.sha256` 文件。`SHA256SUMS.txt` 覆盖三个 EXE、两个 Go ZIP
及 Skill ZIP。三个 EXE 均提供 GitHub Artifact Attestation，另附 `LICENSE`。
下方中英文部分均展示按实际发布文件计算的各 EXE 的 MD5、SHA-1 和 SHA-256。

产品、命令行、MCP 及连接器版本统一为 `0.1.5`，Windows 文件版本为 `0.1.5.0`。
通过测试的 Linux AMD64 容器发布为 `ghcr.io/sagehou/m365-mcp-server:v0.1.5`、
`:0.1.5`、`:0.1` 和 `:latest`。

GitHub Actions 检查 Skill ZIP 的完整文件集合、解压及内部链接、双语文档配对、Python
测试及依赖审计、容器烟测/安全检查、.NET 检查，以及 Go Windows/Linux 测试和
AMD64/ARM64 构建。Skill 压缩包只取发布提交中的已跟踪文件。
