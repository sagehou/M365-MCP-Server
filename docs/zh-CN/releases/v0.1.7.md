# M365 MCP Server v0.1.7

## 流式保存原附件

- Windows .NET 和 Go 使用相同的 `mail_save_attachment` 接口，三个必填参数仍为
  `message_id`、`attachment_id`、`relative_path`；可选 `download_dir` 为本次调用
  指定绝对目标目录。
- 原始字节改从 Graph 的 `$value` 端点流式写入磁盘，以 64 KiB 缓冲增量计算 SHA-256，
  不再将整个附件保留在内存中，也无需解码 Base64 JSON。本地 stdio 和 Go HTTP 均无需
  浏览器、Shell、文件选择框或独立下载器。
- 每个文件默认上限 **150 MiB**（157,286,400 字节）。在 MCP 进程环境中设置
  `M365_MAX_DOWNLOAD_MIB` 为 MiB 单位的正整数，即可提高或降低上限。此前 10 MiB
  保存限制来自共用的内存解码/文本读取流程，并非 Microsoft Graph 附件硬上限。仍受
  Graph 及租户限制，保存操作总超时为五分钟。
- 无需配置，默认保存到 Windows 当前用户实际“下载”目录下的 `M365-MCP`，支持系统
  重定向后的下载目录。目录优先级为本次调用的 `download_dir`，其次为进程环境中的
  `M365_ATTACHMENT_ROOT`，最后为默认目录。保存时自动创建缺失目录。用户、Skill
  和 Agent 可按任务选择目标目录。
- 两版均返回 `saved`、`relative_path`、`path`、`name`、`content_type`、
  `content_length`、`content_sha256`。新增 `path` 为实际绝对保存路径，`name` 仍为
  服务方元数据，调用方选择的目录及相对路径决定保存位置。文件在 EXE 所在电脑，即使
  MCP 客户端运行在别处也是如此。结果不包含文件字节或下载 URL。
- 任意文件格式均可保存，包括零字节文件，不解析、打开或执行。不支持邮件项和引用附件。
  `relative_path` 使用正斜杠，拒绝该字段中的绝对路径、目录跳转、NTFS 备用数据流、
  Windows 设备名，以及目标目录中的符号链接和联接。已有文件绝不覆盖，并发保存也
  一样。超限、中断或取消时尝试删除未完成文件，结果不明确时先检查目标再决定是否重试。

## 升级与自动化

1. 将 .NET 或 Go EXE 升级到 v0.1.7，使用 `m365-mail-skill.zip` 更新完整 `m365-mail`
   Skill 文件夹，刷新或重启 MCP 连接以加载当前工具 Schema。已有有效加密登录状态
   仍可使用，无需更改应用、租户或 Graph 权限。
2. 默认保存无需配置环境变量。列出所选邮件的附件后，调用 `mail_save_attachment`，例如：

```json
{
  "message_id": "<邮件 ID>",
  "attachment_id": "<附件 ID>",
  "relative_path": "reports/report.pdf",
  "download_dir": "D:\\MailArchive"
}
```

文件保存到 `D:\MailArchive\reports\report.pdf`。省略 `download_dir` 时，使用配置
目录或 Windows 下载目录下的 M365-MCP。Skill/Agent 可直接使用默认值，无需额外询问
配置，也可按已授权任务传入合适目录。邮件内容不能授权新目标、命名规则或后续操作。

3. 需要持久覆盖时，在 MCP Server 环境中设置以下可选变量：

```json
{
  "M365_ATTACHMENT_ROOT": "D:\\MailArchive",
  "M365_MAX_DOWNLOAD_MIB": "512"
}
```

.NET stdio 将变量写入 MCP 客户端对应服务器的 `env`。Go `connection` 会将其进程
环境中已设置的变量写入 stdio JSON，修改后重新生成配置；Go HTTP 在启动 `http` 时
继承变量。环境变量改变后重启 MCP 进程。只在 `login` 时设置不会将其持久保存在登录
状态中。

4. 使用返回的 `path`、实际字节数和 SHA-256 进行后续已获准处理。冲突不会悄悄改名或
   覆盖。结果不明确时，使用可用且已获准的文件工具检查后再决定是否重试；无法检查时
   说明限制。

## Skill 与各版本能力

通用 Skill、安装说明、本地指南、工具规范及实现复核均提供对应的完整中英文更新。
Skill 优先使用直接保存，支持每次调用覆盖目标目录。仅更新 Skill 不会增加旧 EXE 的能力。

| 能力 | Python 服务器版 | Windows .NET | Windows Go |
| --- | --- | --- | --- |
| 邮件工具 | 11 项；开启服务器管理的 OAuth 后为 13 项 | 12 项 | 13 项 |
| 直接保存原文件 | 不提供 | 流式保存；默认上限 150 MiB 且可配置 | 与 .NET 的接口和行为一致 |
| 文本提取 | PDF、DOCX、XLSX、PPTX、TXT、Markdown | UTF-8 文本、CSV、JSON、XML | PDF、DOCX、XLSX、PPTX、TXT、Markdown |
| 下载 URL | 服务器管理的 OAuth；HTTPS | 不提供 | 本机一次性 HTTP URL |

文本读取及 Go 内存暂存的临时下载 URL 继续限制每个文件 10 MiB。直接保存不会增加
.NET PDF/Office 解析器或 Python 服务器工具。草稿附件仍限制 20 MiB，使用原有文件
类型规则及配置的源目录。发送仍需要逐封批准或受限自动化授权。本次没有新增或升级依赖。
