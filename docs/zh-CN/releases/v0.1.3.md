# M365 MCP Server v0.1.3

Go 版现在默认使用与 NativeAOT 相同的内置公开 Client ID，直接运行 `login` 即可打开
Microsoft 登录，无需先自行注册应用。

## Go 安全更新

Go 工具链升级为 `1.27.4`，修复 `GO-2026-6859`：标准库 `MaxBytesReader` 的请求头
竞态可能导致 HTTP/1 服务崩溃。

## Microsoft 登录

| 默认配置 | 内容 |
| --- | --- |
| 应用 | M365-MCP-Localhost |
| 公开 Client ID | 6e35216e-2623-43cc-b867-83bec0865cf3 |
| 租户 | organizations |

```powershell
.\m365-mcp-windows-local-go-amd64.exe login
```

使用自建 Desktop/Public Client 应用时，覆盖 Go 登录配置：

```powershell
.\m365-mcp-windows-local-go-amd64.exe login --client-id 你的应用ID --tenant 你的租户ID
```

两套本机版均支持 `M365_LOCAL_CLIENT_ID` 和 `M365_LOCAL_TENANT_ID`。
Go 登录优先级为：命令行参数 → 环境变量 → 内置默认值。无效覆盖值会被拒绝。
登录成功后保存所选应用和租户；切换时先停止服务，再重新登录。重新登录后需重新生成
HTTP 客户端配置。

<details>
<summary>ⓘ 应用注册与授权</summary>

组织部署可自行管理公共客户端应用。两套本机版均使用委托权限，不需要 Client Secret 或
邮箱 Application 权限。内置应用和自建应用都可能因租户策略而需要管理员同意。

</details>

## stdio 接入

登录后，让 MCP 客户端通过 `serve` 参数启动 Go 程序：

```json
{
  "mcpServers": {
    "m365": {
      "command": "C:\\Tools\\m365-mcp-windows-local-go-amd64.exe",
      "args": ["serve"]
    }
  }
}
```

将路径改为实际下载位置。`serve` 默认使用 stdio；`connection` 可自动生成包含实际程序路径
的配置。完整说明见 [Go 指南](https://github.com/sagehou/M365-MCP-Server/blob/v0.1.3/docs/zh-CN/windows-local-go.md)
和 [NativeAOT 指南](https://github.com/sagehou/M365-MCP-Server/blob/v0.1.3/docs/zh-CN/windows-local.md)。

## 发布文件

- `m365-mcp-windows-local-amd64.exe`：NativeAOT，AMD64。
- `m365-mcp-windows-local-go-amd64.exe`：Go，AMD64。
- `m365-mcp-windows-local-go-arm64.exe`：Go，ARM64。
- 每个 EXE 都附 `.exe.sha256` 文件；`SHA256SUMS.txt` 校验三个 EXE 和两个 Go ZIP 包。
  ZIP 包包含使用指南和依赖许可证。
- `LICENSE`；三个 EXE 均提供 GitHub Artifact Attestation。

产品和命令行版本统一为 `0.1.3`，Windows 文件版本为 `0.1.3.0`。
通过测试的 Linux AMD64 容器发布为 `ghcr.io/sagehou/m365-mcp-server:v0.1.3`、
`:0.1.3`、`:0.1` 和 `:latest`。全部构建和测试均在 GitHub Actions 执行。
