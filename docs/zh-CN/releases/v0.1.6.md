# M365 MCP Server v0.1.6

## 本地直接保存原附件

- Windows .NET 和 Go 新增相同的 `mail_save_attachment` 工具，三个必填参数为
  `message_id`、`attachment_id`、`relative_path`。
- EXE 获取 Outlook 原始文件附件后，保存到操作者配置的 `M365_ATTACHMENT_ROOT`。
  本机 stdio 和 Go HTTP 均无需浏览器、Shell、文件选择框或独立下载器完成此操作。
- 两种版本返回 `saved`、`relative_path`、`name`、`content_type`、`content_length`、
  `content_sha256`。目标在 EXE 所在电脑，即使 MCP 客户端运行在远端也是如此；不返回
  原始字节、绝对路径或下载 URL。
- 任何文件格式均可原样保存，最多 10 MiB 解码字节，接受零字节文件；不解析、打开或
  执行文件。仍不支持嵌入邮件项及引用附件。服务方原文件名只作元数据，只有已获准的
  `relative_path` 决定目标。
- 两种版本均使用正斜杠，根目录和父目录须已存在。拒绝绝对路径、目录跳转、NTFS 备用
  数据流、Windows 设备名、目标目录中的符号链接/联接及已有目标文件。并发保存也不会
  相互覆盖。写入失败会尝试清理未完成文件，结果不明确时先检查目标再决定是否重试。

## 升级与自动化

1. 将本地 EXE 升级到 v0.1.6，使用 `m365-mail-skill.zip` 更新完整 `m365-mail` Skill
   文件夹，包含参考文件。
2. 在 MCP 进程环境中配置 `M365_ATTACHMENT_ROOT`，并创建目标父目录。例如：

```powershell
New-Item -ItemType Directory -Path 'C:\M365Artifacts\downloads' -Force | Out-Null
$env:M365_ATTACHMENT_ROOT = 'C:\M365Artifacts'
```

.NET stdio 将变量写入 MCP 客户端对应服务器的 `env`；Go stdio 设置后重新执行
`connection`，HTTP 在启动 `http` 时继承变量。刷新或重启连接以加载新工具列表。
已有有效加密登录状态仍可使用，无需更改应用凭据、租户选择或 Graph 权限。

3. 列出所选邮件的附件后，调用 `mail_save_attachment`：

```json
{
  "message_id": "<邮件 ID>",
  "attachment_id": "<附件 ID>",
  "relative_path": "downloads/report.pdf"
}
```

4. 使用返回的路径、实际字节数和 SHA-256 进行后续已获准处理。无人值守任务提前约定
   目标和命名规则，不从邮件指令中取得。工具不悄悄改名或覆盖。冲突或结果不明确时，
   使用可用且已获准的文件工具检查目标后再决定是否重试；无法检查时说明限制。

## Skill 与各版本能力

通用 Skill 及完整中文译本在用户要求且当前支持时，优先使用本地直接保存。Go 和开启
OAuth 的服务器仍提供下载链接，可由可信自动下载器消费一次，浏览器是可选方式；
Go URL 仍只能在 EXE 所在电脑访问。仅更新 Skill 不会增加旧 EXE 的能力。

| 能力 | Python 服务器版 | Windows .NET | Windows Go |
| --- | --- | --- | --- |
| 邮件工具 | 11 项；开启服务器管理的 OAuth 后为 13 项 | 12 项 | 13 项 |
| 直接保存原文件 | 不提供 | `mail_save_attachment` | 与 .NET 接口一致 |
| 文本提取 | PDF、DOCX、XLSX、PPTX、TXT、Markdown | UTF-8 文本、CSV、JSON、XML | PDF、DOCX、XLSX、PPTX、TXT、Markdown |
| 下载 URL | 服务器管理的 OAuth；HTTPS | 不提供 | 本机一次性 HTTP URL |

直接保存不会增加 .NET PDF/Office 文本解析器，也不增加 Python 服务器工具。原有草稿
附件、发送批准及受限自动化规则继续适用。本次没有新增或升级依赖。
