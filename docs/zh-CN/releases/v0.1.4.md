# M365 MCP Server v0.1.4

## Windows 本机命令与账户

| 配置 | .NET NativeAOT | Go |
| --- | --- | --- |
| MCP stdio 命令 | `stdio` | `stdio` |
| 租户取值 | 租户 GUID、`organizations`、`common`、`consumers` | 租户 GUID、`organizations`、`common`、`consumers` |
| 本机回环 HTTP 命令 | 不提供 | `http --port 8000` |
| 邮件工具 | 11 项 | 12 项，包含附件下载 |

两套本机版继续内置同一个公开 Client ID
`6e35216e-2623-43cc-b867-83bec0865cf3`，默认租户为 `organizations`。
可通过 `M365_LOCAL_CLIENT_ID` 和 `M365_LOCAL_TENANT_ID` 覆盖；Go 还支持
`login --client-id 你的应用ID --tenant 你的租户ID`。
两套版本均不内置、也不需要 Client Secret。

```json
{
  "mcpServers": {
    "m365": {
      "command": "C:\\Tools\\m365-mcp-windows-local-go-amd64.exe",
      "args": ["stdio"]
    }
  }
}
```

将 `command` 改为实际 EXE 路径。.NET 使用 `m365-mcp-windows-local-amd64.exe`，
同样配置 `args: ["stdio"]`。Go 的 `connection` 命令按实际程序路径生成此配置；
`connection --http --port 8000` 生成带认证的 HTTP 配置。

### 从 v0.1.3 及以前版本升级

1. 替换 Go EXE，将 MCP 客户端的 `args: ["serve"]` 改为 `args: ["stdio"]`，或重新
   执行 `connection`。旧 `serve` 命令现在会返回迁移提示。
2. HTTP 启动命令从 `serve --http --port 8000` 改为 `http --port 8000`。
   `stdio` 命令不接受 `--http`。
3. 已有的有效加密登录状态保持兼容，仅升级命令无需重新登录。重新登录会轮换 Go 的
   本机 HTTP Token，之后需重新生成 HTTP 客户端配置。
4. 自建应用仅支持个人 Microsoft 账户时使用 `consumers`，支持组织和个人账户时使用
   `common`，单租户组织应用使用所属租户 GUID。修改 Authority 不会改变应用注册
   支持的账户类型。

<summary>ⓘ 应用注册与授权</summary>

本地版指南已完整说明如何创建桌面/公共客户端、注册 `http://localhost`，以及覆盖两套
版本的默认配置。组织部署建议自行管理独立应用。本机应用使用 `User.Read`、
`Mail.ReadWrite`、`Mail.Send` 委托权限，不需要邮箱 Application 权限或自定义
`access_as_user` API 权限范围。

两套版本目前都请求 `User.Read`，但邮件操作不调用用户资料 API。两套默认流程还请求
`openid`、`profile`、`offline_access`；Go 由 MSAL 自动附加。虽然上述三项 Graph
委托权限本身不强制管理员同意，租户策略仍可要求批准。指南说明了批准后仍出现提示时，
如何比较实际请求的 Scope 与整个组织的授权。仅从门户移除权限不会改变 EXE 的请求。

## 功能与安全修正

- .NET 的关键词加日期查询在 KQL 中组合日期；仅日期查询使用 OData 过滤及收件时间
  排序。拒绝无效日期和类型错误的可选参数。
- .NET 支持通过空数组清空分类，为草稿文本、收件人、资源 ID、MIME 类型及附件大小
  设置明确校验。列出附件时只请求元数据，不下载文件内容。
- .NET 处理异常 Graph 响应和 JSON-RPC 请求时保持 stdio 可用；校验令牌响应与有效期，
  限制加密状态文件读取大小，成功持久化后才在浏览器报告登录成功。
- 公开 OAuth 注册接口在 JSON 解析前将请求体限制为 128 KiB，覆盖流式请求和虚假长度头。
  重定向 URI 限制为 2048 个字符；嵌套过深的异常 JSON 返回客户端错误。
- 清理确认未使用的 Python 包装、配置、导入及从未赋值的 .NET 字段。删除实际不可用的
  第 1 版状态解析分支；有效的第 2 版状态保持兼容。
- 容器改用 Python 3.12 Alpine，应用系统安全更新并保留必需的 C++ 运行库。移除不需要
  的 Debian 工具及安装工具 `pip`/`uv`，保留原有 UID 100、GID 101 和 `/data` 访问权限。
