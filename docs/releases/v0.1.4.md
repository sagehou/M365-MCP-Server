# M365 MCP Server v0.1.4

## Windows local commands and accounts

| Setting | .NET NativeAOT | Go |
| --- | --- | --- |
| MCP stdio command | `stdio` | `stdio` |
| Tenant values | Tenant GUID, `organizations`, `common`, `consumers` | Tenant GUID, `organizations`, `common`, `consumers` |
| Loopback HTTP command | Not provided | `http --port 8000` |
| Mail tools | 11 | 12, including attachment downloads |

Both local editions retain the same built-in public Client ID
`6e35216e-2623-43cc-b867-83bec0865cf3` and default tenant `organizations`.
Override them with `M365_LOCAL_CLIENT_ID` and `M365_LOCAL_TENANT_ID`;
Go also accepts `login --client-id YOUR-APPLICATION-ID --tenant YOUR-TENANT-ID`.
Neither edition embeds or requires a Client Secret.

```json
{
  "mcpServers": {
    "m365": {
      "command": "C:\\Tools\\m365-mcp-windows-local-go-amd64.exe",
      "args": ["stdio"]
    }
  }
}
```

Set `command` to your actual executable path. For .NET, use
`m365-mcp-windows-local-amd64.exe` with the same `args: ["stdio"]`.
Go's `connection` command generates this configuration using its actual path;
`connection --http --port 8000` generates authenticated HTTP configuration.

### Upgrade from v0.1.3 or earlier

1. Replace the Go EXE and change MCP client `args: ["serve"]` to
   `args: ["stdio"]`, or run `connection` again. The old `serve` command now
   returns a migration message.
2. Change HTTP startup from `serve --http --port 8000` to `http --port 8000`.
   The `stdio` command does not accept `--http`.
3. Existing valid encrypted sign-in state remains compatible. Updating commands
   alone does not require another sign-in. Signing in again rotates Go's local
   HTTP token, so regenerate HTTP client configuration afterward.
4. Use `consumers` for a self-managed application registered for personal
   Microsoft accounts only, `common` for organizational and personal accounts,
   and the owning tenant GUID for a single-tenant organization application.
   Changing the authority does not change the registration's account types.

<details>
<summary>ⓘ Application registration and consent</summary>

The local guide now gives complete instructions for creating a desktop/public
client, registering `http://localhost`, and overriding both editions' defaults.
Organization deployments should manage a dedicated registration. Local apps
use delegated `User.Read`, `Mail.ReadWrite`, and `Mail.Send`; they do not need
mailbox Application permissions or a custom `access_as_user` API scope.

`User.Read` is currently requested by both editions, although mail operations
do not use the profile API. Both default flows also request `openid`, `profile`,
and `offline_access`; Go's MSAL library adds these automatically. Tenant policy
can require administrator consent even though the three Graph delegated
permissions do not themselves mandate it. The guide explains how to compare
actual requested scopes with organization-wide grants when approval prompts
persist. Removing a permission from the portal does not change EXE requests.

## Correctness and security fixes

- .NET keyword/date searches combine dates in KQL; date-only searches use
  OData filtering and received-time ordering. Invalid dates and incorrectly
  typed optional arguments are rejected.
- .NET can clear categories with an empty array. Draft text, recipients,
  resource IDs, MIME types, and attachment sizes have explicit validation.
  Attachment listings request metadata without downloading file bytes.
- .NET handles malformed Graph responses and JSON-RPC envelopes without
  terminating stdio. Token responses and lifetimes are validated, encrypted
  state reads are bounded, and browser success follows successful persistence.
- Public OAuth registration limits bodies to 128 KiB before JSON parsing,
  including streamed requests and false length headers. Redirect URIs are
  limited to 2048 characters; deeply nested invalid JSON returns a client error.
- Removed confirmed unused Python wrappers, settings, imports, and unpopulated
  .NET fields. Removed the unusable version-1 state branch; valid version-2
  state remains compatible.
- The container now uses Python 3.12 Alpine with system security updates and
  the required C++ runtime. It removes unused Debian tools and installation
  tools `pip`/`uv`, preserving the existing UID 100, GID 101, and `/data` access.
