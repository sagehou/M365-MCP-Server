# M365 MCP Server v0.1.8

## Folder discovery and moving by name

- The Python server, Windows .NET, and Windows Go all add read-only
  `mail_list_folders` with the same optional inputs: `parent_folder_id` and
  `next_link`. No dependency or permission scope is added.
- Call with `{}` for top-level folders. Each call returns at most 100 visible
  folders at one level in `folders`, with `id`, `displayName`, `parentFolderId`,
  `childFolderCount`, `totalItemCount`, and `unreadItemCount`. It does not
  recursively expand the tree or include hidden folders.
- Pass a returned folder ID as `parent_folder_id` to browse its direct
  children. Continue with the returned `next_link` and the same parent until
  `next_link` is null. For top-level pagination, leave the parent omitted or
  empty. Unicode names, quotes, and same-name folders are preserved.
- For “move this email to Projects/Invoices”, the Agent lists the relevant
  levels/pages, matches the requested name and hierarchy, resolves duplicate
  destinations, then calls the existing `mail_move` with the selected folder
  ID. Display names are not destination IDs. `mail_move` keeps its existing
  inputs and well-known folder support; use its new `message_id` after a move.
- Caller-supplied and Graph-returned continuation links are checked against
  the same folder-list path and bounded pagination parameters. Requests are
  rebuilt through the existing signed-in `/me` client, rather than following
  arbitrary URLs. Equivalent ID encodings and opaque continuation tokens are
  supported. The .NET path check now treats the query separately so `..` in
  a valid cursor is not mistaken for path traversal.
- Folder names carry untrusted-content metadata. Invalid Graph collections
  or continuations return errors rather than appearing as empty or complete
  results. Folder pagination does not add continuation to `mail_search`.

```json
{}
```

```json
{"parent_folder_id": "<returned parent folder ID>"}
```

```json
{"parent_folder_id": "<same parent folder ID>", "next_link": "<returned next_link>"}
```

After resolving the destination, call `mail_move`:

```json
{"message_id": "<message ID>", "destination_folder_id": "<selected folder ID>"}
```

## Windows one-command installation for Agents

```powershell
& ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/sagehou/M365-MCP-Server/v0.1.8/scripts/install-windows-local.ps1')))
```

- The installer defaults to Go, selects the latest stable AMD64/ARM64 package,
  verifies SHA-256 for the package, packaged EXE, and complete Skill archive,
  and installs to `%LOCALAPPDATA%\Programs\M365-MCP`. Windows PowerShell 5.1
  and PowerShell 7 are supported without administrator access or a Go runtime.
- Interactive installation asks for your own application Client ID and tenant
  ID. Blank answers select the shared built-in public Client ID and
  `organizations`. Use the owning directory GUID for a single-tenant custom
  application. No Client Secret or token entry is needed; login uses the system
  browser and the tenant's configured consent policy.
- An Agent can collect the user's application/tenant choice first, then run
  with `-NonInteractive -ClientId '<application-client-guid>' -TenantId
  '<directory-tenant-guid>'`. Use `-SkipLogin` to defer browser sign-in;
  `login-command.txt` records the exact command. `-InstallDirectory` selects
  another absolute installation directory.
- The installer writes `mcp.json` with a stdio entry, installs both language
  guides and the complete `m365-mail/` folder, and preserves the public-client
  login flow. Merge the generated `m365-local` entry into the client's existing
  MCP settings, install the Skill through that client's Skill mechanism, and
  refresh the connection. The installer does not edit client-specific settings
  or silently sign in when `-SkipLogin` is selected. Close the local MCP process
  before reinstalling. Manual .NET and Go installation remains available.

## Upgrade and edition capabilities

1. Deploy the v0.1.8 container or replace the .NET/Go EXE, update the complete
   `m365-mail` Skill folder, and refresh/restart the MCP connection. Existing
   valid encrypted local login state remains usable; these features require no
   new application, tenant, or Graph permission configuration.
2. The shared Skill now resolves folder names and hierarchy before moving,
   continues folder pages, and preserves duplicate candidates. It follows the
   exposed tool list and schemas; updating the Skill alone cannot add folder
   discovery to an older server or EXE. English and Chinese guides, tool
   contracts, installation instructions, and capability counts are aligned.

| Capability | Python server | Windows .NET | Windows Go |
| --- | --- | --- | --- |
| Mail tools | 12; 14 with server-managed OAuth | 13 | 14 |
| `mail_list_folders` | Read-only; one level/page | Same interface | Same interface |
| Transport | Authenticated HTTPS Streamable HTTP | stdio | stdio; authenticated loopback HTTP |
| Direct original-file save | Unavailable | Streaming; configurable 150 MiB default | Same interface and behavior as .NET |
| Text extraction | PDF, DOCX, XLSX, PPTX, TXT, Markdown | UTF-8 text, CSV, JSON, XML | PDF, DOCX, XLSX, PPTX, TXT, Markdown |
| Download URL | Server-managed OAuth; HTTPS | Unavailable | Local single-use HTTP URL |

Original-file saving retains its default Windows Downloads/M365-MCP directory,
per-call `download_dir` override, configurable `M365_MAX_DOWNLOAD_MIB`, and
no-overwrite behavior. Text reading and Go temporary download URLs remain
limited to 10 MiB. Draft attachments retain their 20 MiB limit and existing
file-type rules. Sending still requires per-message approval or bounded
automation authorization. This release does not upgrade or add dependencies.

Each standalone EXE has an `.exe.sha256` file and GitHub Artifact Attestation.
`SHA256SUMS.txt` covers all three EXEs, both Go ZIPs, and the Skill ZIP;
`LICENSE` is included. Both language sections display each EXE's MD5, SHA-1,
and SHA-256 calculated from the exact release assets.

Product, CLI, MCP, and connector versions are `0.1.8`; Windows file versions
are `0.1.8.0`. The Linux AMD64 image is published as
`ghcr.io/sagehou/m365-mcp-server:v0.1.8`, `:0.1.8`, `:0.1`, and `:latest`.

GitHub Actions covers read-only tool schemas and MCP dispatch, folder names and
hierarchy, duplicate names, empty/final pages, skip/skiptoken pagination and
encoding, invalid inputs and provider responses, user identity isolation, and
moving with the returned ID. Windows installer checks cover built-in/custom
IDs, deferred login, generated configuration, packaged files, and rejected
checksum mismatches. Release gates also run Python tests/audits, container
smoke/security checks, .NET checks and NativeAOT builds, Go Windows/Linux race
tests/audits and AMD64/ARM64 packaging, version-info checks, checksums and
attestation. The separate Windows build workflows remain available.

EXEs are unsigned. MD5 and SHA-1 support legacy antivirus allowlist forms;
use SHA-256 and GitHub Artifact Attestation to check provenance. New EXEs need
new allowlist reviews. Live client/Skill behavior, tenant consent, real mailbox
operations, and Windows ARM64 execution require target-environment acceptance.
Automated checks do not guarantee antivirus acceptance or absence of unknown
defects/vulnerabilities. No local tests, builds, dependency installs, or virtual
environments were used. Updated: 2026-11-16.
