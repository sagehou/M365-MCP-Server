# M365 MCP Server v0.1.5

## Shared m365-mail Skill

- Consolidates the four WorkBuddy mail Skills into one portable `m365-mail`
  Skill for the Python server, Windows .NET, and Windows Go editions.
- Uses the connected MCP tool descriptions and input schemas to choose the
  supported workflow, including client-added tool name prefixes. Optional
  tools are called only when exposed by that connection.
- Includes complete English and Chinese instructions, installation/migration
  guides, and separate remote-upload references loaded when needed. The
  package has one `SKILL.md` entry point.
- Retains explicit send approval or bounded automation authorization, final
  draft/attachment review, untrusted-content handling, and protection against
  duplicate writes after ambiguous failures. Skill metadata does not
  preapprove mailbox or shell operations.
- Clarifies that attachment-list `size` is provider metadata, while fetched
  `content_length` is the actual decoded byte count; they are not interchangeable
  integrity values.

## Edition capabilities

| Capability | Python server | Windows .NET | Windows Go |
| --- | --- | --- | --- |
| Mail tools | 11; 13 with server-managed OAuth | 11 | 12 |
| Draft attachment input | `draft_id`, `upload_handle` after binary upload | `draft_id`, optional `relative_path`; omitting it opens the picker | `draft_id`, required `relative_path`; no picker |
| Attachment text | PDF, DOCX, XLSX, PPTX, TXT, Markdown | UTF-8 text, CSV, JSON, XML | PDF, DOCX, XLSX, PPTX, TXT, Markdown |
| Attachment download | Server-managed OAuth only; HTTPS URL | Unavailable | HTTP URL opened on the EXE's PC |
| Remote upload helpers | Server provides upload handles and optional OAuth push grants | `inspect-attachment` and `push-attachment` | No helper commands |

Local path attachments use the operator-configured `M365_ATTACHMENT_ROOT`.
Go requires forward slashes, such as `reports/weekly.docx`. Remote uploads use
a trusted binary uploader and `upload_handle`; a path on the client PC is not
an upload. Download links are temporary, single-use capabilities.

## Install or migrate the Skill

1. Download `m365-mail-skill.zip` and `SHA256SUMS.txt`. Compare the ZIP's
   SHA-256 with its checksum record before extracting.
2. Copy the complete extracted `m365-mail` folder, including `references/`, to
   one client Skill directory:

| Client | Personal directory | Project directory | Explicit invocation |
| --- | --- | --- | --- |
| Codex CLI / IDE | `~/.agents/skills/m365-mail/` | `<project>/.agents/skills/m365-mail/` | `$m365-mail` |
| Claude Code | `~/.claude/skills/m365-mail/` | `<project>/.claude/skills/m365-mail/` | `/m365-mail` |

Windows PowerShell example for personal Codex installation:

```powershell
Get-FileHash .\m365-mail-skill.zip -Algorithm SHA256
Expand-Archive -LiteralPath '.\m365-mail-skill.zip' -DestinationPath '.\m365-mail-skill'
$m365SkillParent = Join-Path $env:USERPROFILE '.agents\skills'
New-Item -ItemType Directory -Path $m365SkillParent -Force | Out-Null
Copy-Item -LiteralPath '.\m365-mail-skill\m365-mail' -Destination $m365SkillParent -Recurse
```

For Claude Code, use `.claude\skills` instead of `.agents\skills`. Other Agent
Skills clients use their own documented directory. Refresh/restart the client
if the Skill has not appeared. `SKILL.md` links to the complete Chinese version;
keep one entry point and use the user's conversation language.

3. Remove the old `outlook-mail`, `outlook-mail-compose`,
   `outlook-mail-management`, and `outlook-attachments` Skill copies from the
   client, or replace its old WorkBuddy package, to avoid duplicate guidance.
4. Configure and sign in to the MCP connection separately. The Skill does not
   configure authentication or grant permissions. WorkBuddy's remote OAuth
   connector template remains in the source archive's `workbuddy/` directory;
   package its contents with `connector-meta.json`, `mcp.json`, `icon.svg`, and
   `skills/` at the ZIP root. The Skill ZIP alone is not a connector package.

Existing valid encrypted login state and `stdio` configurations remain usable.
For Go v0.1.3 or earlier, change `args: ["serve"]` to `args: ["stdio"]` after
upgrading, or run `connection` again. Change `serve --http --port 8000` to
`http --port 8000`. Signing in again rotates Go's local HTTP token; regenerate
HTTP configuration afterward.

| File | Contents |
| --- | --- |
| `m365-mail-skill.zip` | Portable Skill, complete English/Chinese instructions, installation guides, remote-upload references |
| `m365-mcp-windows-local-amd64.exe` | .NET NativeAOT, AMD64 |
| `m365-mcp-windows-local-go-amd64.exe` | Go, AMD64 |

| `m365-mcp-windows-local-go-arm64.zip` | Go ARM64 EXE, both language local guides, dependency licenses |

Each standalone EXE has an `.exe.sha256` file. `SHA256SUMS.txt` covers all three
EXEs, both Go ZIPs, and the Skill ZIP. All three EXEs have GitHub Artifact
Attestation; `LICENSE` is included. Both language sections below display each
EXE's MD5, SHA-1, and SHA-256 calculated from the exact release assets.

Product, CLI, MCP, and connector versions are `0.1.5`; Windows file versions are
`0.1.5.0`. The tested Linux AMD64 container is published as
`ghcr.io/sagehou/m365-mcp-server:v0.1.5`, `:0.1.5`, `:0.1`, and `:latest`.

GitHub Actions checks the Skill ZIP's complete file set, extraction and internal
links, bilingual document pairs, Python tests and dependency audits, container
smoke/security gates, .NET checks, and Go Windows/Linux tests and AMD64/ARM64
builds. The Skill archive comes from the release commit's tracked files.

---

EXEs are unsigned. MD5 and SHA-1 support legacy antivirus allowlist forms;
use SHA-256 and GitHub Artifact Attestation to check provenance. New EXEs need
new allowlist reviews. Live Skill import/client behavior, tenant consent, real
mailbox operations, and Windows ARM64 execution require target-environment
acceptance. Automated checks do not guarantee antivirus acceptance or absence
of unknown defects/vulnerabilities. No local tests, builds, dependency installs,
or virtual environments were used. Updated: 2026-11-12.
