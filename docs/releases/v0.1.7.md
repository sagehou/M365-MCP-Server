# M365 MCP Server v0.1.7

## Stream original attachments to disk

- Windows .NET and Go use the same `mail_save_attachment` interface. The three
  required arguments remain `message_id`, `attachment_id`, and `relative_path`;
  optional `download_dir` selects an absolute destination for this call.
- Original bytes now stream from Graph's `$value` endpoint to disk with a
  64 KiB buffer and incremental SHA-256, without retaining the entire attachment
  or decoding a Base64 JSON payload. No browser, shell, file picker, or separate
  downloader is needed over local stdio or Go HTTP.
- The default per-file limit is **150 MiB** (157,286,400 bytes). Set the MCP
  process environment `M365_MAX_DOWNLOAD_MIB` to a positive integer in MiB to
  raise or lower it. The former 10 MiB save limit came from the shared in-memory
  decoding/text-reading path, not a Microsoft Graph attachment hard limit.
  Graph and tenant limits still apply; the save operation times out after
  five minutes.
- Without configuration, files go to `M365-MCP` inside the current Windows
  user's actual Downloads folder, including system-redirected Downloads.
  Directory priority is `download_dir` for this call, then process environment
  `M365_ATTACHMENT_ROOT`, then the default. Missing directories are created
  when saving. Users, Skills, and Agents can select a task-specific directory.
- Both editions return `saved`, `relative_path`, `path`, `name`, `content_type`,
  `content_length`, and `content_sha256`. The new `path` is the actual absolute
  saved path. `name` remains provider metadata; the caller's directory and
  relative path choose the destination. Files stay on the EXE's PC, including
  when the MCP client runs elsewhere. No file bytes or download URL appear in
  the result.
- Any file format, including zero-byte files, can be saved without parsing,
  opening, or executing it. Mail item/reference attachments are unsupported.
  Use forward slashes in `relative_path`; reject absolute paths in that field,
  traversal, alternate data streams, Windows device names, symbolic links and
  junctions in destination directories. Existing files are never overwritten,
  including concurrent saves. Over-limit, interrupted, or cancelled transfers
  attempt to remove their incomplete file; inspect the destination after an
  ambiguous failure before retrying.

## Upgrade and automate

1. Replace the .NET or Go EXE with v0.1.7, update the complete `m365-mail` Skill
   folder from `m365-mail-skill.zip`, and refresh/restart the MCP connection to
   load the current tool schema. Existing valid encrypted login state remains
   usable; no application, tenant, or Graph permission change is required.
2. No environment configuration is needed for default saves. List the selected
   message's attachments and call `mail_save_attachment`, for example:

```json
{
  "message_id": "<message ID>",
  "attachment_id": "<attachment ID>",
  "relative_path": "reports/report.pdf",
  "download_dir": "D:\\MailArchive"
}
```

This saves to `D:\MailArchive\reports\report.pdf`. Omit `download_dir` to use
the configured directory or Windows Downloads/M365-MCP. The Skill/Agent can
use the default without asking for extra configuration or pass a directory
appropriate to the authorized task. Email content cannot authorize a new
destination, filename policy, or subsequent action.

3. For persistent overrides, set these optional MCP server environment values:

```json
{
  "M365_ATTACHMENT_ROOT": "D:\\MailArchive",
  "M365_MAX_DOWNLOAD_MIB": "512"
}
```

For .NET stdio, put them in the MCP client's server `env`. Go `connection`
includes the variables in stdio JSON when set in its environment; regenerate
that configuration after changes. Go HTTP inherits them when `http` starts.
Restart the MCP process after environment changes. Setting variables only
during `login` does not persist them in login state.

4. Use the returned `path`, actual byte count, and SHA-256 for subsequent
   authorized processing. Conflicts do not silently rename or overwrite.
   Check an ambiguous outcome with an available authorized file tool before
   retrying; if inspection is unavailable, report that limitation.

## Skill and edition capabilities

The shared Skill, installation instructions, local guide, tool specification,
and implementation review have matching English and Chinese updates. The
Skill prefers direct saving and supports per-call directory overrides.
Updating the Skill alone does not add capabilities to an older EXE.

| Capability | Python server | Windows .NET | Windows Go |
| --- | --- | --- | --- |
| Mail tools | 11; 13 with server-managed OAuth | 12 | 13 |
| Direct original-file save | Unavailable | Streaming; configurable 150 MiB default | Same interface and behavior as .NET |
| Text extraction | PDF, DOCX, XLSX, PPTX, TXT, Markdown | UTF-8 text, CSV, JSON, XML | PDF, DOCX, XLSX, PPTX, TXT, Markdown |
| Download URL | Server-managed OAuth; HTTPS | Unavailable | Local single-use HTTP URL |

Text reading and Go's in-memory temporary download URLs retain their 10 MiB
per-file limits. Direct saving does not add a .NET PDF/Office parser or Python
server tools. Draft attachments remain limited to 20 MiB with the existing
file-type rules and configured source directory. Sending still requires
per-message approval or bounded automation authorization. No dependencies
were added or upgraded for this change.
