# M365 MCP Server v0.1.3

The Go edition now uses the same built-in public Client ID as NativeAOT.
Running `login` opens Microsoft sign-in without requiring your own app registration.

## Go security update

The Go toolchain is updated to `1.27.4`, fixing `GO-2026-6859`, an HTTP/1 server
crash caused by a `MaxBytesReader` header race in the standard library.

## Microsoft sign-in

| Default | Value |
| --- | --- |
| Application | M365-MCP-Localhost |
| Public Client ID | 6e35216e-2623-43cc-b867-83bec0865cf3 |
| Tenant | organizations |

```powershell
.\m365-mcp-windows-local-go-amd64.exe login
```

For a self-managed desktop/public-client application, override the Go login:

```powershell
.\m365-mcp-windows-local-go-amd64.exe login --client-id YOUR-APPLICATION-ID --tenant YOUR-TENANT-ID
```

Both editions accept `M365_LOCAL_CLIENT_ID` and `M365_LOCAL_TENANT_ID`.
Go login applies command-line flags, then environment variables, then built-in
defaults. Invalid overrides fail validation. Successful login saves the selected
application and tenant; stop the server and sign in again to change them.
Regenerate HTTP client configuration after signing in again.

<details>
<summary>ⓘ Application registration and consent</summary>

Organization deployments can manage their own public-client registration.
Both local editions use delegated permissions without a Client Secret or
application mailbox permissions. Tenant policy may require administrator consent
for the built-in or a self-managed application.

</details>

## stdio connection

After login, configure the MCP client to start the Go executable with `serve`:

```json
{
  "mcpServers": {
    "m365": {
      "command": "C:\\Tools\\m365-mcp-windows-local-go-amd64.exe",
      "args": ["serve"]
    }
  }
}
```

Set the path to your downloaded executable. `serve` defaults to stdio;
`connection` generates the configuration using the actual executable path.
See the [Go guide](https://github.com/sagehou/M365-MCP-Server/blob/v0.1.3/docs/windows-local-go.md)
or [NativeAOT guide](https://github.com/sagehou/M365-MCP-Server/blob/v0.1.3/docs/windows-local.md).

## Release files

- `m365-mcp-windows-local-amd64.exe`: NativeAOT, AMD64.
- `m365-mcp-windows-local-go-amd64.exe`: Go, AMD64.
- `m365-mcp-windows-local-go-arm64.exe`: Go, ARM64.
- Each EXE has an `.exe.sha256` file. `SHA256SUMS.txt` covers all three EXEs
  and both Go ZIP packages; the ZIPs include guides and dependency licenses.
- `LICENSE` and GitHub Artifact Attestation for all three executables.

Product and CLI versions are `0.1.3`; Windows file versions are `0.1.3.0`.
The tested Linux AMD64 container is published as
`ghcr.io/sagehou/m365-mcp-server:v0.1.3`, `:0.1.3`, `:0.1`, and `:latest`.
All builds and tests run in GitHub Actions.

---

Executables are unsigned. MD5 and SHA-1 support legacy antivirus allowlist forms;
verify SHA-256 and GitHub Artifact Attestation for provenance. New executables
need new allowlist reviews. Windows runtime smoke checks cover AMD64; ARM64 is
cross-compiled with PE metadata checks. Live tenant consent and client behavior
require acceptance on the target PC. Updated: 2026-11-11.
