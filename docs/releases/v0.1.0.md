# M365 MCP Server v0.1.0

Project source code and documentation are released under the
[MIT License](../../LICENSE). Third-party dependencies retain their own licenses.

The first stable release is a self-hosted Outlook Mail MCP gateway for
WorkBuddy-compatible and other Streamable HTTP MCP clients. It deliberately keeps
the tool surface small and confines Microsoft Graph access to the signed-in
user's delegated `/me` mailbox.

## Included

- Microsoft Entra bearer-token validation, tenant allowlisting, and required
  scope enforcement.
- Delegated Microsoft Graph access through On-Behalf-Of (OBO).
- OAuth protected-resource and authorization-server discovery.
- Optional dynamic public-client registration, interactive authorization code
  flow with S256 PKCE, encrypted persistent sessions, refresh-token rotation,
  replay rejection, and restart recovery.
- Per-request identity isolation and safe structured audit events.
- The WorkBuddy connector package and its four scoped Skills.
- Docker and Docker Compose deployment with a non-root runtime and health check.
- A Windows x64 NativeAOT single executable for local stdio integration, published with a SHA-256 checksum and GitHub build-provenance attestation.

## Outlook Mail tools

- `mail_search`
- `mail_get`
- `mail_create_draft`
- `mail_send_draft`
- `mail_list_attachments`
- `mail_read_attachment`
- `mail_download_attachment`
- `mail_mark_read`
- `mail_archive`
- `mail_move`
- `mail_set_category`

Attachment extraction supports PDF, DOCX, XLSX, PPTX, text, and guarded archive
inspection. Parser processes have byte, archive-expansion, resource, timeout, and
cancellation limits. Download tickets are short-lived and single-use.


This release supports `linux/amd64`. It does not claim an ARM64 image.

## Windows executable

The same tag workflow builds and smoke-tests the exact Windows x64 NativeAOT release candidate and publishes:

- `m365-mcp-windows-x64.exe`
- `m365-mcp-windows-x64.exe.sha256`

The executable is unsigned by Authenticode in v0.1.0. Its SHA-256 checksum is published alongside the asset, and GitHub Artifact Attestation provides Sigstore-backed build provenance for the released executable. Verify provenance with `gh attestation verify m365-mcp-windows-x64.exe --repo sagehou/M365-MCP-Server`.

## Release gate

Before creating the `v0.1.0` tag, maintainers must complete and record the
[release checklist](../release-checklist.md), including real WorkBuddy sign-in and
refresh, restart recovery, two-user isolation, cross-tenant isolation, and
representative real-mailbox attachment tests. Mocked CI coverage is not a
substitute for this evidence.

The bounded automation-send contract is included, but its in-policy send and
out-of-policy block were not live-tested for v0.1.0. They are explicit
deployment gates for enabling automated sending, not claims of completed
release acceptance.

The tag workflow verifies that the tag matches `project.version`, belongs to
reviewed `main` history, has bilingual release notes, passes the full Python
suite, builds and smoke-tests the exact production image, builds and smoke-tests the exact Windows executable, verifies its checksum, records build provenance, validates Compose, pushes all image tags, and only then creates the GitHub Release with the Windows assets.

## Known limitations

- Search returns one bounded page and a `next_link` hint; opaque continuation
  cursors are not implemented.
- Folder discovery, replies, forwarding, HTML/attachment composition, shared
  mailboxes, OCR, RBAC, rate limiting, and observability are not included.
- Sending is draft-first and plain-text only. It requires per-message
  confirmation or explicit bounded automation authorization; acceptance by
  Graph is not delivery confirmation, and ambiguous send failures are not
  retried automatically.
- The bounded automation path is supported at the client/agent policy layer,
  but was not live-tested for this release. Validate both an allowed send and
  an out-of-policy block before enabling it in a deployment.
- Calendar, OneDrive, SharePoint, and Teams are not included.
- OAuth remains an explicitly configured feature and should not be enabled before
  the deployment has passed its own real-client acceptance.
- Multi-replica deployment is not supported; transient download tickets and
  SQLite OAuth state assume a single server instance.
- The Windows local stdio runtime is included as an unsigned x64 NativeAOT executable. It exposes ten local mail tools; `mail_download_attachment` and rich PDF/Office attachment extraction remain unavailable in local mode.
